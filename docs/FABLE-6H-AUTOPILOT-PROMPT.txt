TRACK 2 — CONQUER THE SCORER FIELD

Treat Track 2 with the same evidence standard as Track 1. The objective is to
produce canonical scorer candidates that rank correct answers above bad ones on
at least as many hidden/public cases as the incumbent while achieving strictly
better average separation.

Known gate behavior:

1. Ordering is checked first.
2. Candidate must match or beat champion ordering.
3. If ordering passes, candidate average separation must strictly exceed the
   champion, not tie it.
4. A scorer can win by tying ordering and beating separation. This is how
   PREFLIGHT won TEXT_AUTHENTICITY_CHECK registration 1832: ordering 14–14,
   margin 0.6651 versus 0.6586.
5. Passing separation while losing one ordering case still fails. IP scorer
   attempts repeatedly demonstrated this.

Track 2 operating queue:

1. Query the current WASM registry for every intent.
2. Record champion registration, URL, hash, eval ordering, separation,
   comparable cases, worst self-match, standard deviation, and historical rows.
3. Prioritize intents where:
   - a real public/archived corpus exists;
   - the champion's ordering or separation has visible headroom;
   - the scorer ABI can be reproduced locally;
   - a small deterministic module can outperform without overfit.
4. Download champion binaries and verify their keccak256 hashes.
5. Validate a local harness against recorded node scores before optimizing.
6. Construct positive/negative pairs from real receipts, factual mutations,
   omissions, contradictions, stale values, operational-error prose, verbosity,
   malformed answers, and question-answer mismatch.
7. Measure champion ordering and margins on the same corpus.
8. Develop candidate modules in isolated files/branches. Reuse existing scorer
   infrastructure and scripts where available.
9. Test ABI compatibility, determinism, finite [0,1] output, self-match,
   adversarial inputs, memory/runtime, and module size.
10. Produce a decision packet for each candidate: ordering, separation,
    per-case results, champion comparison, worst cases, hash, size, build command,
    and immutable hosting plan.
